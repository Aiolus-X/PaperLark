# PaperLark 使用手册

更新：2026-10-27 · 适用于当前本机试用版，浏览器扩展 0.2.2。

在飞书文档或 PDF 的评论中输入指令，PaperLark 会在同一评论线程回复，也可以生成论文总结、整理讨论和记录待办。普通文档优先使用 `/ask`、`/trans`、`/think`；PDF 支持下表全部指令，其中部分功能仍待真实页面验收。

## 1. 开始使用

1. **确认服务在线**：打开 [本机状态页](http://127.0.0.1:8787/status)，确认飞书已连接。当前依赖这台电脑上的服务，电脑休眠或服务退出会影响回复。
2. **给文档添加 PaperLark 应用**：需要应用能访问该文档；让 PaperLark 写总结，还需要目标位置的写权限。
3. **在启用扩展的 Chrome/Edge 中打开文档**：扩展会自动登记已授权的文档。更新扩展后，在 `chrome://extensions` 点击 PaperLark 的“重新加载”，再刷新飞书页面。
4. **选中文字 → 添加评论 → 输入 `/trans` → 发送**：译文会出现在原评论下面。提问可用 `/ask 问题`，讨论想法可用 `/think 想法`。

已登记文档无需每次 `@PaperLark`。一条评论使用一个指令，指令放在评论开头。命令不区分大小写，下面统一用小写。

| 使用环境 | 当前用法 |
| --- | --- |
| 普通文档 Docx | 官方评论接口提供文字引用；网页登记后，可在网页或飞书桌面客户端中问答、翻译和讨论 |
| PDF 网页 | 精确选区依赖浏览器扩展；安装并刷新后，新建选区评论。可见高亮也依赖网页扩展 |
| PDF 桌面客户端 | 已登记论文可尝试不依赖精确选区的全文指令；新选区原文无法通过当前扩展取得，划词翻译请用网页 |
| 新文档 | 授权后先在启用扩展的网页中打开。纯桌面中只添加应用，不保证服务立即发现 |

首次安装见 [扩展安装说明](BROWSER_EXTENSION.md)。本机未运行服务时，在终端执行以下命令并保持运行；状态页已在线则无需重复启动：

```bash
cd /path/to/PaperLark
npm start
```

## 2. 指令速查

| 指令 | 功能 | 是否需要选区 | 结果位置 |
| --- | --- | --- | --- |
| `/ask 问题` | 解释内容、回答问题 | 可选；只有 `/ask` 时需要选区 | 当前评论线程 |
| `/trans` | 默认将选中内容译成中文 | 需要；明确提供原文或章节时可不选 | 当前评论线程 |
| `/think 想法` | 讨论观点、漏洞和验证方法 | 可选；只有 `/think` 时需要选区 | 当前评论线程 |
| `/sum` | 总结全文的问题、方法、结果与局限 | 不需要 | 当前评论线程 |
| `/key` | 极简提炼全文要点 | 不需要 | 当前评论线程 |
| `/doc` | 创建论文总结文档 | 不需要 | 新 Docx，原线程返回链接 |
| `/highlight` | 提取全文关键原句并尝试显示高亮 | 不需要；仅支持 PDF 网页高亮 | PDF 网页图层，评论确认已保存 |
| `/add` | 将当前讨论整理后追加到总结 | 可选；可依据当前线程或补充要求 | 总结的 Idea List 前 |
| `/compare --path 链接` | 对比当前论文与另一篇论文 | 不需要 | 当前评论线程 |
| `/note 待办内容` | 把想法直接记为 ToDo | 可选；只有 `/note` 时需要选区 | 总结末尾的 Idea List |
| `/pol` | 精简当前线程上一条 AI 回答 | 不需要，但线程内须有 AI 回答 | 当前线程新增回复 |
| `/paper` | 记录一次阅读启动，显示阅读次数等状态 | 不需要 | 当前评论线程 |

别名：`/summary` = `/sum`；`/translate`、`/tran` = `/trans`；`/polish` = `/pol`。

## 3. 问答、翻译和讨论

### `/ask`：理解文档

```text
/ask 这篇论文解决了什么问题？
/ask 这段公式的直觉是什么？
/ask 详细推导这个结论，并说明成立条件
/ask Explain the main limitation --lang English
```

选中一段内容后，也可只评论 `/ask`，默认解释选区。回答结合文档正文、选区和当前线程的讨论；不会读取其他评论线程的对话。

### `/trans`：翻译选区或指定章节

```text
/trans
/trans --lang English
/trans Sec3
/trans Sec3 --lang 中文
/trans 翻译选中内容，保留算法名称和公式
```

默认语言是中文。没有额外指令时只翻译选区；`Sec3` 表示从正文定位第 3 节。也可以在命令后直接附上要翻译的原文。翻译保持完整，不因普通评论的简洁要求而截短。

PDF 的新选区需在启用扩展的网页中创建。扩展安装前的旧批注不会自动补采集；遇到“只收到第 1 页定位”，刷新页面后重新选中原文并新建评论。

### `/think`：讨论自己的想法

```text
/think 我觉得收益主要来自对稀有动作更大的更新，而不一定依赖几何解释
/think 这个方法迁移到多跳问答时，最先需要验证什么？
```

AI 会结合原文讨论依据、反例、局限和实验思路，不默认赞同。选中内容后仅写 `/think`，会围绕选区提出讨论切入点。

AI 回复后，可以在**同一评论线程**直接追问：

```text
如果只做一个实验，应该怎么设计？
这个反例在论文的设置下还成立吗？
```

不必每轮重复 `/think`。新建线程则是新的讨论，不继承其他线程历史。

## 4. 总结与知识整理

### `/sum` 与 `/key`：先快速判断值不值得读

```text
/sum
/key
```

`/sum` 默认最多 5 点，约 250–400 字，覆盖问题、方法、关键结果和局限。`/key` 默认 3–5 条，每条尽量不超过 20 字。两者都面向全文，并在评论中回复。

### `/doc`：生成可继续编辑的总结

```text
/doc
/doc --name "RIPO 阅读笔记"
/doc 重点解释核心公式及其局限
/doc --refresh
```

不需要选中任何文字，始终总结全文。默认标题为 `日期 + 论文题目`，日期按北京时间生成。正文默认约 800–1200 中文字，采用已确认的分享结构：

| 章节 | 内容 |
| --- | --- |
| TL;DR | 一句话核心结论 |
| Motivation | 要解决的问题 |
| Method | 核心机制、必要公式与直觉 |
| Main Result | 最重要的实验结果及条件 |
| 思考 | 局限、疑问、可验证想法 |
| Idea List | 后续 `/note` 写入的待办 |

**默认位置**：由本机 `FEISHU_SUMMARY_FOLDER_URL` 指定，通常设为专门授权的总结父页面。首次安装请填写自己的实际链接。

指定其他位置时使用完整的知识库父页面或飞书文件夹链接。例如，以下命令指定总结父页面；请把示例链接替换为自己的实际链接：

```text
/doc --name "RIPO 阅读笔记" --path https://example.feishu.cn/wiki/SummaryParentToken
```

`--name` 含空格时加引号。`--path` 不接受 `/研究/总结` 这类目录名称；应用必须对目标有写权限。位置优先级为：显式 `--path` → 本机配置的默认位置 → 尝试论文所在知识库的同级目录。

创建失败后，完整生成的草稿会保留；源内容、模板和补充要求未变时，重试 `/doc` 可复用草稿。`--refresh` 会重新调用模型。**成功后再发 `/doc` 会新建另一份总结，不是更新旧文档**；后续 `/add`、`/note` 指向这篇论文最近成功创建的总结，旧文档仍保留。

### `/add`：将讨论整理进总结

前提：先在**这篇源论文**中成功使用 `/doc`。之后在源论文的相关评论线程里发送：

```text
/add
/add 将上面的讨论整理成“局限与验证思路”，保留关键假设
```

AI 会读取当前总结的最新正文，包括人工编辑和已有追加，参考本线程讨论生成一个紧凑小节，尽量避免重复，插入 Idea List 之前。默认一个小标题、2–4 个信息点，约 300 字以内。

可在源论文的不同评论线程下使用，但每次只整理该线程的上下文。**不是在任意文档评论下都能写入 RIPO 总结**；也不支持通过 `/add --path` 任意指定目标。

### `/note`：直接保存一个待办

同样需要先创建该论文的总结，并在源论文中发送：

```text
/note 比较固定裁剪与动态裁剪对低概率动作的影响
/note 改变 rollout 数量，检查探索收益是否仍然成立
```

内容以飞书原生未完成 ToDo 写入总结末尾。当前 `/note` 直接保存你提供的内容，不调用模型扩写；只有 `/note` 时使用选中原文。要先讨论再整理，用 `/think` → `/add`；要落下一条具体行动，用 `/note`。

## 5. 对比、高亮与阅读状态

### `/compare`：比较另一篇论文

```text
/compare --path https://example.feishu.cn/wiki/OtherPaperToken
/compare --path https://example.feishu.cn/wiki/OtherPaperToken 重点比较训练信号、更新机制和计算开销
```

将示例链接替换成另一篇实际论文的飞书链接。PaperLark 会读取双方正文，默认比较方法，也可按补充要求调整重点。另一篇可以是 Docx 或文字型 PDF，应用须能读取；两个链接不能指向同一文档。

### `/highlight`：PDF 关键原句高亮

```text
/highlight
/highlight --clear
```

从全文选择最多 12 处关键原句，先核对原文，再交给扩展定位。再次 `/highlight` 会替换本篇已保存的高亮集合；`--clear` 清除。

扩展面板中的状态含义：

打开位置：Chrome 右上角“扩展程序”（拼图图标）→ **PaperLark · 文档阅读助手**。可以点击图钉固定到工具栏。

| 状态 | 含义 |
| --- | --- |
| 已保存引用／尚未匹配 | 已生成内容，尚未在当前页面定位，不能据此认定已显示 |
| 已定位、当前不可见 | 匹配到了文字，但不在当前可见区域，可滚动到相关页 |
| 当前视图已显示 | 当前视图检测到可见高亮范围 |
| 当前页面尚无法显示 | 暂未识别到可用的 PDF 文字层，需进一步适配或等待页面加载 |

当前是浏览器显示图层，不写回 PDF 文件，不会随下载的 PDF 导出。普通 Docx 不支持此指令。**RIPO 网页高亮已获用户确认**：更新至 0.2.2 后，5 条引用中有 2 处在当时的视图匹配并显示；其他页尚未逐一验收。更新扩展并刷新页面后会复用原引用，无需重发命令。

### `/pol`：让上一条回答更短

在已有 AI 回复的同一线程中发送：

```text
/pol
```

尽量压缩到原长度的一半，保留关键事实、条件和行动项。它会新增一条精简回复，不覆盖旧评论，也不改写总结文档。

### `/paper`：记录阅读启动

```text
/paper
```

按“用户 + 论文”累计调用次数，显示首次／第 N 次阅读、总结链接、Idea 记录数和高亮数。**每调用一次都会增加一次阅读计数**，不是自动识别打开次数、阅读百分比或已读页数。Idea 数来自 PaperLark 保存的记录，不会根据手动勾选待办实时重算。

可以选中标题后在评论中调用；直接在文档标题文本中输入 `/paper` 还不会唤起 Agent。

## 6. 一次完整阅读的用法

每一步单独发送；第 3–5 步尽量留在同一讨论线程：

1. `/paper` 记录本次阅读，再用 `/key` 看核心要点。
2. 遇到难句，选中并评论 `/trans`；遇到概念或公式，用 `/ask`。
3. `/think 我觉得这个方法可能依赖……`，然后自然语言追问。
4. `/doc` 生成总结；已有总结时可跳过。
5. `/add 把上面的讨论整理成局限与后续实验`，将讨论留下来。
6. `/note 完成一个具体的对照实验`，把行动放到 Idea List。

## 7. 输出、上下文和等待时间

- **风格**：默认结论优先、简洁、高信息密度。普通问答和讨论通常约 150–350 中文字；可在 `/ask`、`/think` 或 `/doc` 后明确要求详细推导。字数是生成指引，不是硬截断。
- **模型**：可在 [个人设置页](http://127.0.0.1:8787/app) 修改 API 地址、Key、模型和推理强度，保存后新任务生效。未启用自定义配置时使用 `.env` 中的默认值，详见 [模型配置](MODEL_SETTINGS.md)。
- **线程记忆**：问答和讨论携带当前线程最近最多 12 条、合计最多 30,000 字符的历史；不合并其他线程。
- **正文读取**：普通选区翻译只发送选中内容；问答、讨论及全文指令会按需要携带正文。相同版本的正文会缓存，避免重复下载和解析，但缓存不代表每次调用模型都不用再次输入正文。
- **执行**：同线程依次处理，不同线程默认最多并发 3 个任务；同一论文的文档写入串行。`/note`、`/paper` 不调用模型，`/doc` 命中草稿也可跳过生成。
- **等待**：评论轮询默认约 15 秒一次，之后还需模型处理。普通模型请求默认 180 秒超时，`/doc` 为 600 秒；这不是承诺的响应时间。无需连续重复发送同一指令。

## 8. 当前验证范围与常见问题

| 范围 | 当前状态 |
| --- | --- |
| PDF 精确选区翻译、普通 Docx 翻译和 `/ask` | 已有真实飞书回复，并已读回或获用户确认 |
| RIPO `/doc` | 已实际创建总结，读回验证目录、标题、章节、公式和评论链接 |
| `/think` | 文档上下文、真实模型和线程测试通过；飞书连续讨论仍待用户验收 |
| `/sum`、`/key`、`/add`、`/compare`、`/note`、`/pol`、`/paper` | 已实现并有自动化覆盖；相应真实操作仍待验收 |
| PDF 高亮 | 隔离 Chromium 测试通过；RIPO 当前视图显示已获用户确认，其余页未逐一验收 |
| 打开即用 | 网页扩展自动登记已实现；纯桌面首次发现、多用户 PDF 共用仍有限制 |

**没有回复**：先看本机状态页，再看扩展是否“已接入”当前文档。已授权的新文档先用网页打开；核心指令 `/ask`、`/trans`、`/think` 支持补处理最近 24 小时未答评论，历史 `/doc` 等写操作不会自动重放。

**PDF 只拿到页码／等待选区超时**：确认扩展启用并已刷新页面，重新选中文本后新建 `/trans` 评论；扩展面板可检查待上传记录。当前不能从页码自动猜出原句。

**`/doc` 权限不足**：给 `FEISHU_SUMMARY_FOLDER_URL` 或 `--path` 指定的目标位置授予写权限；给原 PDF 加应用不等于给其整个知识库写权限。

**`/doc` 提示已部分写入**：先打开错误回复中的文档链接检查，避免重复创建；完整草稿会保留。`/add` 找不到 Idea List 时，检查该标题块是否被移动或删除。

**别人能否使用**：取决于应用发布范围及文档授权。普通 Docx 不限定开发者本人；当前 PDF 扩展桥接一次配对一个阅读者，多用户共享和跨企业直接安装尚未完成。

**支持哪些内容**：新版 Docx 和可提取文字的 PDF。Docx 保留可读公式、列表与表格文字，但尚未读取图片本身；扫描 PDF 尚无 OCR，旧版 Docs 暂不支持。

详细完成情况见 [功能清单](../FEATURES.md)，接入说明见 [权限与分享](ACCESS_AND_SHARING.md)，开发者说明见 [执行模型](EXECUTION_MODEL.md)。
