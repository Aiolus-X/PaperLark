# 保留原 PDF：浏览器扩展安装与试用

本项目保留原 PDF，通过浏览器扩展补充选区，不依赖 macOS 辅助功能。

## 已安装用户更新到 0.2.2

在 `chrome://extensions` 找到 PaperLark，点击重新加载，再刷新飞书网页。无需删除或重新配对。0.2.2 补充嵌套组件中的 PDF 文字层查找、组件内的高亮样式和显示状态的延迟更新。之前保存的引用会继续使用，无需重发 `/highlight`。

文档仍须授权应用访问。登记成功后，扩展弹窗显示当前文档；已登记 Docx 也可在桌面客户端继续使用。PDF 的精确新选区及可见高亮需要网页扩展。

## 本机安装

首次使用先执行 `npm run extension:setup` 生成自己的本机配对配置。Chrome / Edge 操作：

1. 打开 `chrome://extensions`（Edge 用 `edge://extensions`）。
2. 开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择：

   `/path/to/PaperLark/extension`

4. 刷新已经打开的飞书论文网页。扩展必须在页面加载时挂接请求。
5. 在原 `RIPO.pdf` 中选中文字，**新建一条评论** `/trans` 并发送。
6. 页面右下角出现“PaperLark：选区已关联到这条评论”，随后 AI 在原线程回复。

文档链接示例：`https://example.feishu.cn/wiki/ExamplePaperToken`，请替换为自己的论文。

扩展安装前已有的评论不会自动补采集。首次验收请新建选区评论，而不是仅回复旧线程。无需在评论中附加原文或特殊参数。

## 工作方式

飞书保存 PDF 划词引用时，网页发起 `POST /space/api/box/comment/add/`。用户提供的真实请求表明，它包含：

```json
{
  "file_token": "PdfFixtureToken00000000000",
  "comment_id": "7000561436094762017",
  "extra": {
    "drive_area_coordinate": {
      "type": 4,
      "position": { "page": 0, "text": "Beyond Euclidean Clipping:" }
    }
  }
}
```

扩展观察现有 fetch / XMLHttpRequest 请求，在成功响应后只提取文件 Token、评论 ID、文字、页码和文档版本。它不重放或修改飞书请求，不读取请求头、Cookie、CSRF 或登录令牌，也不修改原 PDF。

引用由独立扩展后台发送到本机服务；模型密钥、飞书 App Secret 始终留在后端。后端用官方评论 API 验证作者和页码，并按 `fileToken + commentId` 精确关联。不会根据“最近一次鼠标选区”猜测对应关系。

事件先到时，任务进入 `waiting_selection`，默认等待 120 秒；引用到达后自动继续。超时会明确回复，稍后送达仍可恢复这条失败翻译。重复事件和引用不会重复生成 AI 回复；不同文件或不同读者不会混用引用。

## 状态与重试

点击浏览器工具栏中的扩展图标：

Chrome 右上角“扩展程序”（拼图图标）→ **PaperLark · 文档阅读助手**。也可点击图钉，将 PaperLark 固定到工具栏。

- “本机服务已连接”表示配对配置和本地服务正常。
- “待上传”是暂存的引用数；网络恢复后扩展会自动重试，也可点击“检查连接并重试上传”。
- “需处理”表示作者、页码或引用冲突等校验失败；检查配对账号和服务日志后手动重试。
- “网页自动捕获”只统计扩展上传的记录，不把开发时手工回放的样例当作网页捕获。
- 高亮状态区分“已保存引用”“已定位”和“当前视图已显示”。评论确认保存引用，不等于页面已经出现黄色高亮。

本机服务状态：http://127.0.0.1:8787/status 。历史失败任务可能仍在列表中；新任务的 `selectionSource` 应为 `browser-extension`。

## 重新配对 / 换机器

```bash
npm run extension:setup
npm start
```

配置脚本从已有真实评论中确定当前阅读者，并生成独立的选区桥接密钥。若存在多个阅读者，可指定 `npm run extension:setup -- --reader=ou_你的OpenID`。本地版本一次配对一个阅读者。

- `data/browser-bridge.json`：服务端配对身份和桥接密钥。
- `extension/connection.local.json`：扩展访问本机服务的配置。
- 两个文件均仅当前用户可读写，且已忽略版本管理；扩展配置不含模型密钥和 App Secret。

更换配置后，重启本机服务，在扩展管理页点击重新加载，然后刷新飞书页面。不要分发包含 `connection.local.json` 的个人配对副本。

## 验证与边界

`npm test` 验证关联、身份/页码检查、顺序竞争、持久化、重复投递和 HTTP 鉴权。`npm run test:browser` 使用真实 Chromium 加载 MV3 扩展，以隔离的飞书请求样例与模型替身检查 fetch/XHR、原请求完整性、成功/失败响应、断线重试和原线程回复；不读取用户浏览器配置或登录 Cookie。

真实 RIPO.pdf 选区翻译已通过：服务记录 `browser-extension` 来源，并在原线程回复，用户确认成功。0.2.2 的自动登记、网页内跳转、普通及嵌套封闭文字层高亮、面板状态另有隔离 Chromium 测试。

2026-10-27，真实 `/highlight` 生成并保存 5 处原文引用，0.2.1 未匹配到文字层。更新至 0.2.2 后，RIPO 当前视图回传 2 处匹配、2 处可见范围，用户明确确认“看到了”。当前页面显示已验收；其余引用页和其他 PDF 布局未逐一验证。真实页面回传未发现 Shadow DOM，不能把嵌套组件当作已证实的故障原因；本版还扩大了文字层选择器和页容器查找。

网页请求路径及字段属于飞书前端实现，可能随升级变化；未捕获时会等待或报错，不使用整页替代选区。当前不在飞书桌面客户端内运行扩展。
