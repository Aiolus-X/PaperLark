# 权限、知识库与 Docx 写入

## 三层权限分别验证

| 层级 | 要核对的内容 | 常见误判 |
| --- | --- | --- |
| 应用权限 | 当前身份对应的 API scope 已开通、发布并获审批 | 控制台勾选成功就以为已生效 |
| 应用可用范围 | 已发布版本包含文档所有者/使用者 | 同事看不到文档应用，被误判为文档未分享 |
| 资源权限 | 论文、模板、输出父节点分别可读/可写 | 用户自己可读，或者 PDF 已加应用，就以为应用能编辑整个知识库 |

用实际接口结果验证权限生效，不根据应用版本号是否变化猜测。读取论文、读取模板、模型生成、创建文档、写正文、追加 ToDo 是不同失败阶段，应在错误消息中保留阶段。

曾遇到创建总结时依次出现：缺少节点创建 scope、scope 开通后又缺少目标知识空间编辑权限。解决后一种问题应授权具体输出父页面，或按官方流程授予空间编辑成员，而不是继续扩大 API scope。能用编辑权限完成的操作，不要求用户授予管理员权限。

## 知识库与输出路径

- `/wiki/<node>` 先通过 `wiki/v2/spaces/get_node` 解析 `obj_token`、`obj_type`、`space_id` 和 `parent_node_token`。
- 创建总结子文档时使用父页面节点；创建同级时使用源节点当前的父节点。论文移动后重新读取父节点，不沿用旧缓存。
- 根节点父 Token 可以为空，但根目录创建仍需要空间层面的写权限。源文件可读不能证明根目录可写。
- 明确路径优先级：用户显式路径、已配置默认路径、源文档同目录。无法可靠定位同目录时返回具体引导，不静默写到其他目录。
- 用 `--path` 表示文件夹/知识库链接时，不把人类目录名伪装成已经解析的路径。

## 读取文档

Docx blocks 能保留标题、列表、表格与公式；仅用 raw_content 可能丢失公式。按子节点顺序遍历，保留表格行列关系，图片明确标为未读取，不把占位符当作视觉理解。

共享文档可能允许读取最新 blocks，却不允许指定历史 revision。曾遇到“文档元数据和最新正文可读，指定 revision 返回 forbidden”的情况。可读取 `document_revision_id=-1`，前后检查版本；版本变化时有限重试，不缓存混合版本。不能把每个 forbidden 都归为用户漏授权。

PDF 文件下载后验证文件头、大小与可提取文字。扫描文件要明确 OCR 状态。文件名可能只是缩写；论文标题可优先使用可靠元信息或首页提取，并允许用户指定标题。

## 写入可靠性

- 文档创建前保存完整生成草稿。草稿命中条件包含正文、模板和用户要求；用户要求重生成时绕过缓存。
- 创建新文档后记录待写入状态，完成正文和必要章节后再将其设为当前总结。替换失败不能丢失原本完整的总结链接。
- 生成结果转换为原生标题、列表、公式和 ToDo；检查数学分隔符与常数/参数定义，避免格式化或摘要压缩改变公式含义。
- `/add` 等追加操作应读取最新总结，考虑人工编辑和已有追加；把文档更新与本地“成功”记录放在正确顺序。
- 同文档写入串行，遵守每批 block 数量限制。已知限流可退避；网络断开、超时或不确定写入结果需先查远程状态，不无条件重试。
- 对“先写正文，再写章节，再回复链接”分别记录结果。回复评论失败不应触发重新生成或重复创建总结。
- 本地 JSON 存储只支持单实例时，不开两个进程写同一文件。多实例部署需要另做任务锁与共享持久化。
